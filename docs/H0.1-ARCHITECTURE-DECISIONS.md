# H0.1 Architecture Decision Records

- Document ID: AL-H01-ADR-001
- Version: 1.0.0
- Status: Decisions for H1 planning; runtime choices remain provisional pending benchmarks
- Date: 2026-11-27

## ADR-001 — Rust is the sole language and execution authority
**Decision:** Lexer, parser, AST, name resolution, type/semantic checks, AL-IR validation, capability policy and runtime enforcement belong to the Rust AL core.
**Alternatives:** LLM interpretation/execution; Python as language runtime; plugins defining core semantics.
**Reason:** One deterministic authority avoids split-brain semantics and prevents generated text bypassing safety.
**Consequence:** AI is an optional proposal layer. Rust validates all candidate source. Core remains useful without Python or a model.

## ADR-002 — Python is the model research and training environment
**Decision:** Python handles data preparation, model experiments, training, evaluation and controlled conversion/export. Rust owns production AL semantics and execution.
**Alternatives:** All ML in Rust; Python as production authority.
**Reason:** Python has a mature research ecosystem; Rust keeps core deterministic and deployable.
**Consequence:** Python is not required to run AL core. Artifacts cross a versioned manifest/checksum boundary.

## ADR-003 — JSON Lines is the first Rust–Python bridge
**Decision:** One JSON object per line over stdin/stdout; protocol version on every message; stdout is protocol-only, stderr for logs.
**Alternatives:** PyO3/FFI immediately; local HTTP; shared mutable database.
**Reason:** Process isolation, inspectability, low coupling and simple failure handling.
**Consequence:** Define request ids, message size, timeout, cancellation, error envelope and restart. Reconsider FFI only after profiling/security review.

## ADR-004 — Standard Rust collections before specialized containers
**Decision:** Start with Vec/String/HashMap/HashSet; use BTreeMap for ordered iteration/range queries. Add arenas, ropes or custom allocators only after profiling.
**Reason:** Current lexer is small and dependency-free; premature specialization increases maintenance burden.
**Consequence:** H1 measures allocations, peak memory and throughput before optimization.

## ADR-005 — Canonical source spans use UTF-8 byte offsets
**Decision:** Persist half-open byte ranges [start,end) into immutable UTF-8 source snapshots. SourceMap derives line, grapheme and display columns.
**Alternatives:** Unicode scalar offsets only; display columns as canonical offsets.
**Reason:** Byte offsets support exact slicing; display columns depend on grapheme width, tabs and rendering.
**Consequence:** Current Span uses character offsets; migration must be deliberate and versioned. Test Vietnamese combining marks, emoji and CRLF. Never silently reinterpret existing spans.

## ADR-006 — SQLite FTS5/BM25 is the first lexical RAG candidate
**Decision:** Benchmark SQLite FTS5 as optional local lexical index. Keep document registry/retrieval API independent. Embeddings/reranking are later optional stages.
**Alternatives:** Vector DB first; remote search; custom inverted index immediately.
**Reason:** Deterministic offline baseline without a neural model; FTS5 supplies full-text search and ranking.
**Consequence:** Verify FTS5 build and Vietnamese tokenization. Default tokenization may not satisfy Vietnamese segmentation; test before selection. Not part of compiler core.

## ADR-007 — llama.cpp/GGUF and ONNX Runtime are benchmark candidates
**Decision:** Benchmark llama.cpp CPU inference with quantized GGUF for local generative models. Benchmark ONNX Runtime CPU for compact encoders/classifiers/embedders. Use Transformers primarily for Python research/training.
**Alternatives:** Vendor API lock-in; Transformers as default 4 GB runtime; unbenchmarked mandatory runtime.
**Reason:** Runtime roles differ. Official docs describe CPU/quantized inference for llama.cpp, execution providers for ONNX Runtime, and model/quantization workflows for Transformers.
**Consequence:** No production model/runtime is selected. Verify versions, operators, model card, license, tokenizer, memory and target-device quality.

## ADR-008 — Deterministic baseline before every learned component
**Decision:** Every AI task starts with rules, templates, lexical retrieval or statistical baseline. Learned model admitted only when it improves held-out metrics within risk/resource budget.
**Reason:** Baselines quantify model value and provide fallback.
**Consequence:** Intent routing, retrieval, extraction and code suggestion need separate datasets and metrics.

## ADR-009 — Domain science is modular and provenance-bearing
**Decision:** Physics, chemistry, biology, earth/environment, agriculture and engineering are domain packages with equations, units, assumptions, parameter sources, validity ranges, uncertainty and reference tests.
**Alternatives:** Encode all science in grammar/core; treat LLM prose as solver.
**Reason:** Scientific validity is domain-specific and evolves independently from language syntax.
**Consequence:** H1 designs quantity/unit contracts before solver APIs.

## ADR-010 — Deny-by-default execution and explicit capability grants
**Decision:** Program/AI requests carry requested capabilities; only trusted policy and explicit user approval can grant. Validation-only, dry-run and execution are distinct.
**Reason:** Generated programs and retrieved documents are untrusted.
**Consequence:** Rust validates capability names, resource scopes, limits and audit events. Model output cannot grant access.

## ADR-011 — Local-first with a no-model Lite mode
**Decision:** AL core, deterministic tools and lexical retrieval remain usable without a loaded LLM. AI modules are optional and memory-budgeted.
**Reason:** Target PC is CPU-only with ~4 GB RAM; model weights are not total runtime memory.
**Consequence:** No automatic model load in Lite mode. Benchmark peak RSS, startup, first token, throughput, disk and quality.

## ADR-012 — No model weights or training dataset are selected in H0.1
**Decision:** H0.1 selects no LLM checkpoint, tokenizer, training corpus, embedding weights or production dependency.
**Reason:** Weights, tokenizer, dataset, code and licenses may have different restrictions; hardware suitability is unmeasured.
**Consequence:** H1 creates task cards and lawful dataset inventory before training or weight release.
