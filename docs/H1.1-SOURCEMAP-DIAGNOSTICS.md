# H1.1 — SourceMap, UTF-8 spans and diagnostics

**Status:** First implementation slice on branch `h1-1-source-map-diagnostics`.

## Goals

- Make UTF-8 byte offsets the canonical source coordinate system.
- Keep spans half-open: `[start, end)`.
- Derive human-readable line and column coordinates from a `SourceMap`.
- Render structured diagnostics without making display columns part of compiler semantics.
- Preserve correct slicing around Vietnamese and other multibyte UTF-8 text.

## Implemented

- `Span` now documents and represents UTF-8 byte offsets.
- `Lexer` retains character-based scanning but records byte offsets for every token and lexical error.
- `SourceMap` maps valid UTF-8 byte boundaries to one-based line and Unicode-scalar column coordinates.
- `SourceMap` recognizes LF, CRLF and bare CR line endings.
- `SourceMap::slice` rejects out-of-range, reversed and non-character-boundary spans.
- `Diagnostic` carries a stable code, severity, message and optional source span.
- CLI lexical errors use source-aware diagnostic rendering.
- Lexer treats CRLF as one newline token.

## Coordinate contract

1. Compiler-facing spans are UTF-8 byte offsets, not character indices.
2. A span's end is exclusive.
3. A valid span boundary must be a UTF-8 character boundary.
4. Display line and column are derived; they must never be persisted as source identity.
5. The current column counts Unicode scalar values. It is not a grapheme-cluster count or terminal-cell width. A later diagnostic-rendering slice may add grapheme and display-width support without changing byte spans.

## Test coverage added

- Multibyte Vietnamese text and byte-accurate token slicing.
- Combining-mark input without invalid UTF-8 slicing.
- LF, CRLF and bare CR source mapping.
- Rejection of invalid UTF-8 boundaries and out-of-range offsets.
- Unicode-aware diagnostic location.
- CRLF tokenization as one newline.

## Compatibility and migration

The previous lexer used character indices in `Span`. This change intentionally migrates those values to UTF-8 byte offsets. Any downstream code that treated span values as character indices must be updated. The current lexer is the only known span producer in the bootstrap implementation.

## Not included

- Parser and AST.
- Parser recovery or diagnostic aggregation.
- Grapheme-cluster and terminal display-width calculation.
- A complete source-file registry for multi-file projects.
- Cargo test execution evidence. Tests are committed but must be run in a Rust 2024 toolchain before merge.
