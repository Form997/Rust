# H0.2.3 — Rust Rulebook Validator

**Status:** Proposed implementation; not an approved Rulebook policy.
**Branch:** `h0-2-3-rust-rulebook-validator`

## Implementation

- `src/rulebook.rs` implements record-kind dispatch, semantic checks and a report containing errors and warnings.
- `src/main.rs` adds a dedicated `al rulebook validate` command. The existing `al <source.al>` lexer path remains available.
- `serde_json` is used to parse JSON records.
- CI runs Rust unit tests and CLI smoke tests in addition to JSON Schema validation.

## CLI

```sh
cargo run -- rulebook validate bundle path/to/bundle.json
cargo run -- rulebook validate metric-card path/to/metric-card.json
cargo run -- rulebook validate source-record path/to/source-record.json
cargo run -- rulebook validate decision-record path/to/decision-record.json
cargo run -- rulebook validate training-run-manifest path/to/training-run.json
```

Exit codes: 0 when no validator errors are found; 1 for invalid input or validation errors; 2 for CLI usage errors. Warnings do not fail validation.

## Enforced semantic invariants

1. Approved metric threshold: non-null/non-blank value and at least one evidence ID.
2. Source record: HTTPS official URL; a source marked verified also needs a review date. Unverified status and unknown Vietnam adoption are warnings.
3. Approved decision: approval state must be approved, with a named approver and timestamp. A proposed decision cannot carry an approved approval state.
4. Training/fine-tuning: Rulebook status must be approved; every dataset must have verified license status and a provenance reference; governance review must be approved.
5. Approved bundle: approval state must be approved; included sources must be marked verified and included rules must be approved.

## Tests

Unit tests cover:
- accepted proposed metric with threshold NOT_SET;
- rejection of approved metric without value/evidence;
- warning for an unverified source;
- acceptance of proposed decision;
- acceptance of evaluation-only manifest;
- rejection of training without approval and dataset-rights gates;
- rejection of approved decision without named approver.

CI runs `cargo test --all-targets` and positive/negative CLI smoke tests. A green CI run is required before this implementation can be called tested.

## Security and scope limits

- This module validates selected semantic invariants; JSON Schema remains responsible for the full record shape.
- An HTTPS URL is not proof that a source is official. The validator does not fetch or authenticate remote sources.
- It does not recompute artifact or dataset checksums, establish copyright/licensing, judge scientific validity, or replace legal review.
- It does not approve a Rulebook, train a model, execute AL code, or grant runtime capabilities.
- Rulebook approval remains a separate human-governed action.
