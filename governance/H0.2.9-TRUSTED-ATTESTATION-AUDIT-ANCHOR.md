# H0.2.9 — Trusted Attestation & Immutable Audit Anchor

**Status:** Implementation candidate; requires CI verification and security review.
**Parent:** H0.2.8 branch `h0-2-8-evidence-verification-audit`.
**PR target:** H0.2.8 branch only; no merge to `main`.

## Deliverables

- `src/attestation_anchor.rs`: audit anchor generation/verification and strict invocation of GitHub CLI attestation verification.
- `governance/schemas/audit-anchor.schema.json`: machine-readable anchor contract.
- CI creates a ledger head anchor and signs its provenance using `actions/attest-build-provenance`.
- CI verifies the attestation with both GitHub CLI and AL's fail-closed wrapper, requiring:
  - repository `Form997/Rust`;
  - signer workflow `.github/workflows/rulebook-schema.yml`;
  - SLSA provenance predicate;
  - GitHub-hosted runner (self-hosted runners denied).

## Trust model

The anchor binds:
1. the full ledger SHA-256;
2. the final audit record SHA-256;
3. the final sequence number.

The GitHub artifact attestation binds the anchor file to a verified signer identity and workflow. A later audit verification compares the local ledger against the attested anchor. Any change to the anchored ledger changes its digest and is rejected.

The official GitHub CLI performs signature, certificate identity, transparency-log and subject-digest verification. AL does not implement Sigstore cryptography itself and fails closed if `gh` is missing, unauthenticated where authentication is required, or returns failure.

## Important limitations

- An attestation proves provenance under the configured GitHub trust model; it does not prove that the workflow's claims are scientifically correct or that a human approved the underlying policy.
- Workflow identity must be protected with branch rules, CODEOWNERS/reviews and restricted workflow permissions. For stronger isolation, move attestation signing into a separately governed reusable workflow that callers cannot modify.
- This phase attests a fresh audit anchor during CI. Production must retain the attested anchor and ledger, verify each new head against the previous trusted head, and define retention, recovery and revocation procedures.
- GitHub's transparency-backed attestation is an external cryptographic witness, not an absolute guarantee against compromise of GitHub, the trusted workflow, repository administration or the user's verification environment.
- No live production deployment, hardware security module, independent third-party witness or complete subsystem-gate integration is claimed.

## Commands

```sh
cargo run -- rulebook audit-anchor-create <ledger.jsonl> <anchor.json>
cargo run -- rulebook audit-anchor-verify <ledger.jsonl> <anchor.json>
cargo run -- rulebook attestation-verify <subject-file> <owner/repo> <owner/repo/.github/workflows/workflow.yml>
```

The final command requires an installed and appropriately authenticated GitHub CLI. It delegates cryptographic verification to `gh attestation verify` and requires the specified signer workflow and SLSA provenance predicate.
