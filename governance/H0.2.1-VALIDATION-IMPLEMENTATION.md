# H0.2.1 — Rulebook schema validation implementation

- Version: 0.1.0
- Status: Implemented in branch; CI execution pending GitHub Actions
- Date: 2026-11-27

## Delivered

1. A proposed rulebook bundle fixture at `governance/bundles/al-rulebook-0.1.0.proposed.json`.
2. A deliberately incomplete negative fixture at `governance/fixtures/invalid-rulebook-missing-required.json`.
3. A GitHub Actions workflow at `.github/workflows/rulebook-schema.yml`.

## CI checks

- Check the JSON Schema against its declared meta-schema.
- Validate the proposed bundle fixture.
- Confirm that the incomplete fixture is rejected.

The negative test is important: a validator that only accepts the sample cannot demonstrate that invalid manifests are blocked.

## Scope and limitations

- This validates JSON structure and declared constraints only.
- It does not verify whether cited standards exist, are current, apply to AL, or have been adopted in Vietnam.
- It does not verify signatures, checksums against bundle contents, approval authority, legal compliance, metric validity, or runtime policy enforcement.
- The proposed fixture is explicitly `proposed`, not an approved active rulebook.
- Workflow execution has not yet been observed. Do not report CI success until GitHub Actions returns a passing run.

## Next implementation
